# Deployment

Build one immutable OCI image per app and worker. GitHub Actions runs verify, builds, pushes, captures registry digests, signs both digests with keyless Sigstore, verifies the signatures in staging, deploys staging by digest, runs smoke and live-fire, and prepares production. Production is MANUAL: set `API_IMAGE_DIGEST` and `WORKER_IMAGE_DIGEST` to the exact `sha256:` digests captured after the verified push, then run `API_IMAGE="ghcr.io/${GITHUB_REPOSITORY}@${API_IMAGE_DIGEST}" WORKER_IMAGE="ghcr.io/${GITHUB_REPOSITORY}-worker@${WORKER_IMAGE_DIGEST}" fly deploy --config fly.toml --app "$FLY_APP_PRODUCTION" --image "$API_IMAGE" --strategy rolling && fly deploy --config fly.worker.toml --app "$FLY_APP_WORKER_PRODUCTION" --image "$WORKER_IMAGE" --strategy rolling`. `GITHUB_REPOSITORY` must be the exact owner/repository path used by the release workflow; do not substitute an unscoped owner variable. A successful GitHub OIDC/registry run remains required before production release. Run migrations with a release command before traffic only when backward compatible. Rollback both apps to a previously verified signed digest with a compatible schema.

Before the manual production deploy, define `API_IMAGE` and `WORKER_IMAGE` as above and verify both exact digests with the same workflow identity and issuer used in staging: `cosign verify "$API_IMAGE" --certificate-identity-regexp "^https://github.com/${GITHUB_REPOSITORY}/.github/workflows/release.yml@.*$" --certificate-oidc-issuer https://token.actions.githubusercontent.com && cosign verify "$WORKER_IMAGE" --certificate-identity-regexp "^https://github.com/${GITHUB_REPOSITORY}/.github/workflows/release.yml@.*$" --certificate-oidc-issuer https://token.actions.githubusercontent.com`. Abort if either verification fails; never substitute a tag or an unverified digest.

The worker Fly app is intentionally private: `fly.worker.toml` must not declare `[http_service]` or `[[services]]`, and the worker health server binds only to `127.0.0.1` inside the VM. The release workflow deploys `fly.worker.toml` separately so the worker receives the `worker-runtime` image with native media tools; the API manifest must not be used as a worker substitute. Before staging deployment, create the declared scratch volume with `fly volumes create worker_scratch --app family-historian-worker-staging --region ord --size 30`; the manifest mounts it at `/tmp` only for the worker process. Inject `WORKER_DATABASE_URL` for the `family_historian_worker` login and run `corepack pnpm --filter @family-historian/database migrate` before starting the worker; never give the worker the owner `DATABASE_URL`. Hosted sandbox attestation is still required for syscall, egress, cgroup/PID, read-only-root, filesystem mode, and scratch controls; the volume declaration is an implementation artifact, not proof that the external volume exists or is correctly hardened.

The attestation must use `worker-sandbox-attestation/v1`, include the exact `deployment_image_digest`, `deployment_app`, and `deployment_worker_id`, and carry an Ed25519 signature verified against the separately supplied `WORKER_SANDBOX_EVIDENCE_PUBLIC_KEY_FILE`. Set `WORKER_SANDBOX_EVIDENCE_EXPECTED_IMAGE_DIGEST`, `WORKER_SANDBOX_EVIDENCE_EXPECTED_APP`, and `WORKER_SANDBOX_EVIDENCE_EXPECTED_WORKER_ID` before running `scripts/probes/worker_sandbox_evidence.sh`; a structurally valid, self-signed, or differently deployed document is not sufficient.
