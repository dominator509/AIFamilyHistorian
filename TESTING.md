# Testing

Unit tests cover domain rules and the media executor's no-shell, path-confinement, timeout, and unavailable-tool behavior. Integration tests use real PostgreSQL, Redis, object storage emulator only when protocol-compatible, and actual provider sandboxes. E2E uses the real web and API entry points. Test doubles are legal only in `tests/unit/doubles` and never in live-fire. Every core outcome maps to a named E2E and live-fire proof. Flaky tests are bugs and cannot be retried until green. Accessibility uses axe and keyboard flows. Performance uses k6; the repository also provides a bounded 100-request API latency smoke via `sh scripts/performance-smoke.sh`. Security includes tenant isolation, IDOR, upload, prompt injection, DLP, consent, deletion, and emergency-access abuse.
Authenticated provider verification includes `sh scripts/probes/deepgram_api_key.sh` and `sh scripts/probes/deepgram_transcription.sh`; the latter asserts a non-empty transcript response, request completion, and bounded provider response handling without persisting sample audio or provider content.
